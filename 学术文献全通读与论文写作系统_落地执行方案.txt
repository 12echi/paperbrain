一、 深度工程审查：原方案存在的 6 大落地致命陷阱与对策
--------------------------------------------------------------------------------

【致命陷阱 1：老旧/复杂排版 PDF 导致的解析雪崩与脏数据污染】
- 现实问题：
  学术论文并不全是规范的现代数字 PDF。遇到较早的扫描版论文（1990-2010 年 IEEE/Springer）、
  公式字体特殊或跨页复杂大表时，MinerU/Docling 偶尔会把乱码当公式，或把多张子图（Fig 1a, 1b, 1c）
  切成一整块包含无关留白的废图。脏数据一旦存入知识库，后续所有分析全部中毒。
- 工程加固防线：
  1. 【双轨自适应解析引擎】：先用轻量代码（PyMuPDF）检测文本可提取率。若数字文本率 > 90%，
     直接采用高精版面分析；若为老旧扫描件，自动路由至专门的 OCR 管道。
  2. 【公式合法性过滤器】：提取出的 LaTeX 公式必须通过轻量级语法校验器（如 `katex` 或 `sympy`
     的预解析）；无法通过校验的乱码强制回退为行内纯文本，防止下游崩溃。
  3. 【复合子图二次分割机制】：针对包含 (a)(b)(c) 的组合图，利用 OpenCV/BBox 轮廓检测进行
     二次切分，分别与 Sub-caption 对齐。

【致命陷阱 2：四遍透读引起的 Token 爆炸、高昂账单与速率限制（Rate Limit）】
- 现实问题：
  一篇 10 页的顶会论文通常有 12,000+ 词（约 18,000 Token）外加 8~10 张图。
  如果原方案每一遍精读都无脑将“全文 + 所有图片”打包送给大模型，单篇论文 4 遍下来将消耗
  超过 80,000 Token 和 40 次多模态调用！处理 50 篇文献将耗费数小时，不仅极易触发 API 的
  每分钟请求上限（TPM/RPM 限流），成本更是呈指数上升。
- 工程加固防线（按章节分治，精准投喂）：
  - 第 0 步（切分章节）：解析完后立即按逻辑拆解为 Abstract, Intro, Method, Exp, Conclusion。
  - 第 1 遍（宏观骨架）：仅投喂【Title + Abstract + Intro + Conclusion】（约 3,000 Token，降本 85%）。
  - 第 2 遍（微观机制）：仅投喂【Methodology / Model Formulation】章节（约 4,000 Token）。
  - 第 3 遍（消融审讯）：仅投喂【Experiments + Ablation Tables + Figures】（约 5,000 Token + 图片）。
  - 第 4 遍（审稿批判）：**不再读取原文**，而是将前 3 遍生成的结构化分析纪要作为输入（约 3,500 Token）。
  ★ 加固收益：单篇论文总 Token 从 80,000 暴降至 15,000 以内，成本缩减 80%，且支持第 2 遍和
     第 3 遍并行并发执行！

【致命陷阱 3：知识图谱中的“毛球效应”（Hairball Problem）与无用实体泛滥】
- 现实问题：
  如果不加约束地让大模型抽取论文中的实体，图谱中会出现海量诸如“model”、“data”、“performance”、
  “accuracy”、“algorithm”等毫无检索价值的通用词，形成密不透风的“杂草图谱”，检索时准确率断崖下跌。
- 工程加固防线（强类型本体约束 Schema）：
  严格限制大模型只允许提取 6 类强学术实体与 5 类关系：
  - 实体白名单：
    1. `[Algorithm/Model]`（如: FlashAttention-v2）
    2. `[Dataset/Benchmark]`（如: HumanEval, ImageNet-1k）
    3. `[Evaluation Metric]`（如: BLEU-4, FLOPS, Latency）
    4. `[Theoretical Component]`（如: Cross-Entropy with Label Smoothing）
    5. `[Problem/Task]`（如: Long-sequence Hallucination）
    6. `[Limitation/Artifact]`（如: Quadratic Memory Footprint）
  - 关系白名单：`Improves_Upon`、`Evaluated_On`、`Contradicts`、`Vulnerable_To`、`Requires`。
  所有不在白名单内的泛化词在存库前一律清洗过滤。

【致命陷阱 4：学术写作时的“引文漂移”与幽灵引用（Citation Drift）】
- 现实问题：
  即使在 System Prompt 中强调必须标注引文，大模型生成长文本时仍会出现“张冠李戴”（把论文 A
  的结论标注为论文 B）或虚构某页不存在的 Figure 标号。
- 工程加固防线（两阶段确定性事实校验门禁）：
  大模型写完草稿后，后台自动执行正则扫描，捕获所有 `[Ref-X, Sec Y]` 标记：
  1. 事实核查器（Fact Verifier）：检索上下文缓存，检查 Paper X 的 Sec Y 中是否真有该结论；
  2. 若证据匹配度低于阈值，系统在界面打上黄色警示标记 `⚠️ [待核实引文]`，绝不静默放行；
  3. 点击该标记，在侧边栏直接高亮对比“模型写的话”与“原文出处对应的句子”。

【致命陷阱 5：长文生成的上下文截断与逻辑崩塌】
- 现实问题：
  写 Related Work 或大篇幅 Method 综述时，若一次性请求生成数千字，大模型往往虎头蛇尾，前两段
  深刻犀利，后面草草收场。
- 工程加固防线（树状大纲递归生成，借鉴 Stanford STORM）：
  1. 第一步：先依据记忆图谱生成三级细化大纲（含每个论证小节对应的核心文献清单）；
  2. 第二步：用户在界面微调/确认大纲结构；
  3. 第三步：以小节（Sub-section）为单位分块独立生成，最后调用全局一致性 Agent 补充承上启下的
     过渡句（Transitions）。

【致命陷阱 6：个人电脑（Mac/日常硬件）的算力与环境配置冲突】
- 现实问题：
  用户使用的是 Mac（macOS 环境），如果同时在本地运行 MinerU 大模型、Docling 视觉服务以及
  本地 7B-VL 视觉大模型，会瞬间榨干 16GB/24GB 统一内存，导致系统严重卡顿甚至 Python 进程 Crash。
- 工程加固防线（轻量混合架构方案）：
  - 推荐解耦部署：
    * **文档预处理（本地）**：Mac 仅运行 Docling/MinerU 的轻量解析模式，或通过 Docker 容器化隔离；
    * **高负载多模态推理（云端极速 API）**：图表精读调用云端视觉模型 API（如 Qwen2.5-VL 或 Claude），
      推理成本极低（单次仅几分钱），完全不占用 Mac 本地显存与风扇；
    * **图谱与向量存储（本地）**：使用无服务器依赖的 LightRAG + SQLite / DuckDB，零常驻显存开销。

三、 关键补丁实现：确定性引文后置校验器 (Citation Verifier) 代码
--------------------------------------------------------------------------------
在学术写作模块后，必须挂载以下后置拦截脚本，彻底铲除幻觉：

```python
import re
from typing import List, Dict

class CitationVerifier:
    def __init__(self, ground_truth_chunks: Dict[str, str]):
        # ground_truth_chunks 保存着本次写作从知识库检索出的所有合法片段
        # key: "PaperID_SectionID", value: "原文内容"
        self.ground_truth = ground_truth_chunks

    def verify_draft(self, draft_text: str) -> Dict:
        # 正则捕获类似 [Ref: 2024_NeurIPS_01, Sec 3.2] 的标记
        citation_pattern = r"\[Ref:\s*([^,\]]+),\s*([^\]]+)\]"
        matches = re.finditer(citation_pattern, draft_text)
        
        verification_report = []
        for match in matches:
            ref_id = match.group(1).strip()
            sec_id = match.group(2).strip()
            key = f"{ref_id}_{sec_id}"
            
            if key not in self.ground_truth:
                verification_report.append({
                    "citation": match.group(0),
                    "status": "UNVERIFIED",
                    "reason": f"引文出处 {key} 不在本次检索到的有效文献片段中！"
                })
            else:
                verification_report.append({
                    "citation": match.group(0),
                    "status": "PASS",
                    "source_excerpt": self.ground_truth[key][:150] + "..."
                })
                
        return {
            "is_clean": all(item["status"] == "PASS" for item in verification_report),
            "report": verification_report
        }
```
